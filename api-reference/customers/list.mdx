List all customer profiles in your account for CRM synchronization, bulk operations, or compliance reporting. Filter by contact details or opt-in status to target specific segments, and page through large datasets using the `page` and `per_page` parameters. Results are returned in reverse chronological order — most recently created first.

## Endpoint

```http
GET https://api.e-receipt.com/v1/customers
```

## Query parameters

<ParamField query="email" type="string">
  Filter by exact email address. Returns at most one result. Use this to look up a customer when you have their email but not their E-Receipt ID.
</ParamField>

<ParamField query="phone" type="string">
  Filter by exact phone number in E.164 format (e.g., `+15551234567`). Returns at most one result.
</ParamField>

<ParamField query="email_opted_in" type="boolean">
  Filter by email opt-in status. Pass `true` to return only customers who accept email receipts, or `false` to list those who have opted out.
</ParamField>

<ParamField query="sms_opted_in" type="boolean">
  Filter by SMS opt-in status. Pass `true` to return only customers who accept SMS receipts, or `false` to list those who have opted out.
</ParamField>

<ParamField query="page" type="integer">
  Page number to retrieve. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  Number of customer profiles to return per page. Defaults to `20`. Maximum `100`.
</ParamField>

## Example request

```bash cURL
curl "https://api.e-receipt.com/v1/customers?email_opted_in=true&page=1&per_page=20" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

## Response fields

Each object in the `data` array is a full customer profile. The `meta` object describes pagination state.

<ResponseField name="data" type="array">
  Array of customer profile objects matching your filter criteria. Each object contains the same fields as a single customer retrieved via `GET /v1/customers/{id}`.
</ResponseField>

<ResponseField name="data[].id" type="string">
  Unique identifier for the customer, prefixed with `cus_`.
</ResponseField>

<ResponseField name="data[].name" type="string">
  The customer's full name.
</ResponseField>

<ResponseField name="data[].email" type="string">
  The customer's email address. `null` if not on record.
</ResponseField>

<ResponseField name="data[].phone" type="string">
  The customer's phone number in E.164 format. `null` if not on record.
</ResponseField>

<ResponseField name="data[].preferred_channel" type="string">
  The default delivery channel — either `"email"` or `"sms"`.
</ResponseField>

<ResponseField name="data[].email_opted_in" type="boolean">
  Whether the customer has opted in to receive receipts by email.
</ResponseField>

<ResponseField name="data[].sms_opted_in" type="boolean">
  Whether the customer has opted in to receive receipts by SMS.
</ResponseField>

<ResponseField name="data[].metadata" type="object">
  Your custom key-value pairs attached to this customer profile.
</ResponseField>

<ResponseField name="data[].created_at" type="string">
  ISO 8601 timestamp of when this customer profile was created.
</ResponseField>

<ResponseField name="data[].updated_at" type="string">
  ISO 8601 timestamp of the most recent update to this customer profile.
</ResponseField>

<ResponseField name="meta.total" type="integer">
  Total number of customer profiles matching your filters across all pages.
</ResponseField>

<ResponseField name="meta.page" type="integer">
  The current page number returned.
</ResponseField>

<ResponseField name="meta.per_page" type="integer">
  The number of results per page used for this response.
</ResponseField>

<ResponseField name="meta.total_pages" type="integer">
  The total number of pages available at the current `per_page` setting.
</ResponseField>

<Tip>
  To find a specific customer when you only know their email or phone number, use the `email` or `phone` query parameter instead of iterating through pages. These filters perform an exact match and return results instantly.
</Tip>

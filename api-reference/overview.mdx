The E-Receipt REST API gives you full programmatic control over receipt creation, customer management, and delivery triggering. Every request and response uses JSON, making it straightforward to integrate with any server-side language or HTTP client.

## Base URL

All API requests go to the following base URL:

```
https://api.e-receipt.com/v1
```

Include this prefix before every endpoint path shown in this reference. For example, to list receipts you would call `https://api.e-receipt.com/v1/receipts`.

## Versioning

The current API version is `v1`, and it is embedded directly in the URL path. When E-Receipt introduces breaking changes — such as removing a field or altering the shape of a response — the version number increments (for example, to `v2`). Non-breaking additions, like new optional fields or new endpoints, are rolled out within the existing version without notice. Pin your integration to the version in the path to avoid unexpected changes.

## Request Format

Send all request bodies as JSON and include the appropriate content type header:

```
Content-Type: application/json
```

Follow these conventions when constructing request payloads:

- **Timestamps** — use ISO 8601 format, always in UTC. For example: `2025-03-15T14:00:00Z`
- **Currency amounts** — express as decimal numbers in the currency's major unit, without currency symbols. For example, use `13.50` to represent $13.50.

## Response Format

Successful requests return an HTTP `2xx` status code and a JSON body containing the requested or created resource.

```json
{
  "id": "rcp_01j9k2m4n5p6q7r8s9t0",
  "object": "receipt",
  "status": "delivered",
  "created_at": "2025-03-15T14:00:00Z"
}
```

When a request fails, E-Receipt returns an HTTP `4xx` or `5xx` status code alongside a structured error object:

```json
{
  "error": {
    "code": "invalid_customer",
    "message": "No customer found with id cus_abc123"
  }
}
```

See the [Errors reference](/api-reference/errors) for a full list of error codes and handling strategies.

## Pagination

Endpoints that return collections of resources are paginated. The response envelope contains a `data` array and a `meta` object with pagination details:

```json
{
  "data": [...],
  "meta": {
    "page": 1,
    "per_page": 20,
    "total": 150
  }
}
```

Control which page you receive using query parameters:

```
GET /v1/receipts?page=2&per_page=50
```

The default page size is `20`. The maximum allowed value for `per_page` is `100`.

## Rate Limits

The API enforces a limit of **100 requests per minute** per API key. Every response includes the `X-RateLimit-Remaining` header so you can track how many requests you have left in the current window:

```
X-RateLimit-Remaining: 84
```

If you exceed the limit, the API returns a `429 Too Many Requests` response. Implement exponential backoff and retry logic in your integration to handle this gracefully. See the [Errors reference](/api-reference/errors#rate-limit-handling) for a code example.

## Sandbox Environment

E-Receipt provides a fully isolated sandbox environment for testing your integration without sending real receipts to real customers:

```
https://sandbox.api.e-receipt.com/v1
```

To use the sandbox, generate a sandbox API key from your dashboard (it will be prefixed with `erecp_test_`) and substitute the sandbox base URL for the production one. All API endpoints behave identically to production, but no emails or SMS messages are actually delivered.

<Note>
  Never use a live API key against the sandbox URL, or a sandbox key against the production URL. Each environment validates that the key type matches.
</Note>

Every request to the E-Receipt API must be authenticated. Authentication is performed by passing your API key as a Bearer token in the `Authorization` header. Requests without a valid key are rejected with a `401 Unauthorized` response.

## Getting Your API Key

You generate and manage API keys from the E-Receipt dashboard. To create a new key:

1. Log in to [app.e-receipt.com](https://app.e-receipt.com).
2. Navigate to **Settings → API Keys**.
3. Click **Create New Key**.
4. Enter a descriptive name for the key (for example, `Production Server` or `CI Pipeline`).
5. Copy the key immediately — it is shown only once and cannot be retrieved again.

If you lose a key before saving it, revoke it and create a new one.

## Making Authenticated Requests

Include your API key in the `Authorization` header of every request:

```text
Authorization: Bearer YOUR_API_KEY
```

Here is a complete example using cURL:

```bash
curl https://api.e-receipt.com/v1/receipts \
  -H "Authorization: Bearer erecp_live_abc123..."
```

The same request in JavaScript and Python:

<CodeGroup>

```javascript JavaScript
const response = await fetch('https://api.e-receipt.com/v1/receipts', {
  headers: {
    'Authorization': 'Bearer erecp_live_abc123...'
  }
});

const data = await response.json();
```

```python Python
import requests

response = requests.get(
    'https://api.e-receipt.com/v1/receipts',
    headers={'Authorization': 'Bearer erecp_live_abc123...'}
)

data = response.json()
```

</CodeGroup>

## API Key Types

E-Receipt issues two types of API keys, each scoped to a specific environment:

| Key Prefix | Environment | Behavior |
|---|---|---|
| `erecp_live_...` | Production | Receipts are created and delivered to real customers |
| `erecp_test_...` | Sandbox | Receipts are processed but no emails or SMS messages are sent |

Use sandbox keys during development and testing to avoid sending unintended communications to customers. Switch to a live key only when you are ready to go to production. See the [Sandbox environment](/api-reference/overview#sandbox-environment) section for more details.

## Keeping Keys Secure

Your API key grants full access to your E-Receipt account. Treat it with the same care as a password.

- **Do not embed keys in client-side code.** Keys in browser JavaScript or mobile apps can be extracted by anyone inspecting your app.
- **Do not commit keys to source control.** Store them in environment variables or a secrets manager instead.
- **Use environment variables** to inject keys at runtime:

```bash
export ERECEIPT_API_KEY="erecp_live_abc123..."
```

Then reference the variable in your application:

<CodeGroup>

```javascript JavaScript
const apiKey = process.env.ERECEIPT_API_KEY;
```

```python Python
import os
api_key = os.environ.get('ERECEIPT_API_KEY')
```

</CodeGroup>

- **Rotate immediately if compromised.** Go to **Settings → API Keys → Revoke** to invalidate the key, then generate a replacement.

<Warning>
  Never log your API key or include it in error reports, support tickets, or application traces. If a key is exposed, revoke it from the dashboard immediately — even a brief window of exposure can allow unauthorized access to your account and customer data.
</Warning>

## Authentication Errors

If the API cannot authenticate your request, it returns one of the following errors:

| Status | Error Code | Cause |
|---|---|---|
| `401 Unauthorized` | `missing_api_key` | No `Authorization` header was included in the request |
| `401 Unauthorized` | `invalid_api_key` | The key is malformed, revoked, or does not exist |
| `403 Forbidden` | `insufficient_permissions` | The key is valid but does not have permission for the requested action |

Check that your key is correctly copied, that you are not mixing live and sandbox keys across environments, and that the `Authorization` header is formatted exactly as `Bearer <key>` with a single space after `Bearer`.
